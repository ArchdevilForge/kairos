## 2. 数据集、样本切分与统计口径（100% 沿用 Phase 2b）

### 2.1 数据集锚点（沿用 `PHASE2B_PREREG.md`）
- **时间跨度**：`2025-11-09T00:00:00Z`（`1762646400`）至 `2026-11-09T23:59:00Z`（`1794268740`），连续 `366` 个日历日（12 个月），严禁挑子窗口。
- **采样结构**：`40` 个等距连续 `1m` K 线切片（前 39 个切片各 `15h = 900` 根 1m K 线，间距 `~9.15 天 >> 24h`，第 40 个切片为末尾 `24h`）+ 全窗口连续 `4h` / `1d` HTF K 线（`fact_perp_bars_htf`）+ 因果滚动 24h 成交额（`fact_perp_volume_24h`）+ `8h` 资金费率（`fact_perp_funding_8h`）+ `5m` OI（`fact_perp_oi_5m`）。
- **PIT 标的池（`PHASE2B_27_SWAP_INST_IDS`）**：15 个主流/核心永续合约 + 12 个 2025–2026 期间上线或中小流动性永续合约（共 27 标的）。任何时刻 `t` 严格校验 `list_ts <= t` 且 `(delist_ts IS NULL OR delist_ts > t)`。
- **步骤 0 验收硬门槛**：重演落库后 `fact_perp_bars_1m` 总行数须在 `758,013 ± 2%`（即 `[742,853, 773,173]`）内，超差即停机报告。

### 2.2 样本切分（沿用 Phase 2b 的 IS / Walk-Forward OOS 切法）
- **Wave 聚类**：所有事件/票据严格按 `tools/research/clustering.py:build_wave_clusters` 的 `< 24h`（`86,400s`）合并规则生成独立宏观波次簇 `wave_cluster_id`。由于相邻 1m 切片间隔 `~9.15 天 >> 24h`，全窗口最多形成 `40` 个独立波次簇。
- **IS / OOS 切分**（与 `tools/research/h3_experiment.py:621-628` 及 `h1_experiment.py:690-728` 完全一致）：
  - **In-Sample（IS / Full Window）**：全部波次簇 `all_cluster_ids`（诊断展示）。
  - **Walk-Forward Out-of-Sample（OOS，所有判决的主口径）**：将首个波次簇 `all_cluster_ids[0]` 作为初始预热校准簇，其后的全部独立波次簇 `oos_cluster_ids = all_cluster_ids[1:]` 作为样本外测试集；任何用到历史参考分布的量只允许读取 `ts < cluster_start_ts` 的历史观测，且所有入场/过滤/排序特征均强制通过 `validate_ex_ante_grouping`（`feature_ts <= entry_ts`，零前视）。
  - **附加稳健性透明度列**：除上述与 2b 完全一致的 Walk-Forward OOS 主口径外，报告同时附列严格按日历前 30% 簇（前 12 个切片）与后 70% 簇（后 28 个切片）不重叠切分的诊断结果；**最终 PASS/FAIL 判决唯一绑定上述 2b 标准 Walk-Forward OOS 口径，严禁在两种切分间挑结果**。

### 2.3 统计口径与基线票流（沿用 Phase 1/2b `PolicyNetR` + `CR1`）
- **收益标尺（`PolicyNetR`）**：统一使用 Phase 1 P0 平台期胜出策略 `wave_k_be=0.8`（`tools/research/policies.py:simulate_holding_policy`，`max_hold_minutes=1440`）：
  - 1m K 线内同时触及止损与目标/保本触发位时，严格按 **`stop-first`（最坏路径优先）** 结算；
  - 含手续费保本止损在确认分钟收盘后，于**下一分钟开盘**生效；
  - 15m/1h/4h 因果抬高波段低点（HL）移动止盈仅使用 `close_ts <= bar.open_ts` 的已收盘 K 线；
  - 全额扣除双边 Taker 5 bps、基础滑点（主流 1.5 bps / 山寨 5.0 bps）、平方根市场冲击滑点 `0.5 * (ATR_1m / P) * sqrt(V / ADV_5m)`（单笔名义本金 `$10,000`）以及持仓跨越的 `8h` 资金费率。
- **聚类稳健推断**：统一使用 `clustering.py` 的 `cluster_robust_mean` 与 `cluster_robust_diff`（`CR1` 聚类稳健三明治方差，按 `wave_cluster_id` 聚类，自由度 `df = G - 1`，双侧 95% Student-t 置信区间与单侧 `student_t_one_sided_p`）。
- **基线票流定义（`Baseline Ticket Stream`）**：
  - 沿用 `tools/research/h1_experiment.py:run_h1_experiment` 的既有因果候选票据生成器（PIT 有效合约、`24h` 成交额门槛 `$30,000,000`、5m 横截面唤醒 + `_detect_5m_pullback_trigger` 因果触发，即 Phase 2b `N = 1,550`、`G = 40` 的同一条 kairos 标准候选票流）。
  - 鉴于源文件 §11（「总原则：不做逆势单。主升浪里他一笔空单都没有」）及改造总纲映射表（「点位 3/5 摸顶空默认排除，默认 OUT，不进 3a」），S1/S2/S3 均为顺势多头设置：
    - **S1 / S2 的比较基线**：主口径对比同一 OOS 波次窗口内的**基线多头票流**（`direction == "UP"`），同时在报告中透明列出对比**全方向基线票流**（`UP + DOWN`）的数值作为核查参照；主判决绑定对基线多头票流的 `OOS ΔNetR`（避免因空单表现差异造成方向性混杂）。
    - **S3 / F 的全票流**：直接在上述 kairos 既有候选票流上做因果划分（S3 在既有顺势多头 pullback 票流上划分「满足浪浪小分歧四约束保留组」vs「违背约束剔除组」，并附全方向票流对照；F 在基线票流上划分「箱体中段/箱体内反弹被滤组」vs「其余保留组」）。

  - **与 Phase 2b `H3:BOX_BREAKOUT` 的本质区别**：H3 的 `BOX_BREAKOUT`（`h3_experiment.py:303-369`）仅在 **过去 4 小时（`48 x 5m`）** 微观窗口内找振幅 `<= 6%` 的小横盘、允许做空、且仅要求到最近阻力 `>= 1.0R`；S1 严格建立在 **多日 `4h`/`1d` 大级别箱体平台** + **上方无近距离日线压力** + **收敛末端极小结构止损** 之上。
- **因果操作化公式（时刻 `t = close_ts_5m`，仅用 `<= t` 已收盘数据，剔除 BTC 自身，PIT 有效且 `24h` 成交额 `>= $10M`）**：
  1. **大级别箱体/平台存在性（源文件 §3 点位 1、§5 第 108 行）**：取 `<= t` 最近 `36` 根已收盘 `4h` K 线（`6` 天大级别平台窗口，排除末尾刚收盘的突破观察段后取前 `[4, 36]` 根构造箱体）：
     - 箱体上沿 `B_hi` 与下沿 `B_lo` 由已确认 `4h` 摆动高低点（确认滞后 `k_4h = 1` 根 `4h` K 线，即 `confirm_ts <= t`）聚类得到（边界容差 `±1.5%`）；
     - 平台跨度至少持续 `>= 12` 根 `4h` K 线（`>= 48h` 大级别整理），且箱体振幅 `4.0% <= (B_hi - B_lo) / B_lo <= 35.0%`（排除 `<4%` 的日内微噪音与 `>35%` 的失控暴跌）。
  2. **中界信号已完成（源文件 §5 第 98 行「二次探顶/二次探底为中界」）**：该 `4h` 箱体内已因果确认的上沿试探次数 `upper_probes >= 2` **且** 下沿试探次数 `lower_probes >= 2`（至少间隔 2 根 `4h` K 线的不相邻触碰）。
  3. **末端波动率收敛走完（源文件 §5 第 103、109 行）**：突破前最近 `3` 根已收盘 `4h` K 线平均振幅（TR）相对箱体前段 `12` 根 `4h` K 线平均振幅压缩比 `ATR_4h_ratio <= 0.85`，**或** `5m` 级别近 `6` 根（30m）相对前 `24` 根（2h）振幅压缩比 `ATR_5m_ratio <= 0.85`。
  4. **向上结构突破与量能确认（源文件 §5 第 106–110 行、§7 第 129 行 VELO 案「超大级别盘整后的启动需要量能与突破幅度确认」）**：
     - 当前 `5m` 收盘价向上突破大级别箱体上沿 `B_hi`（`c_t > B_hi` 且前一根 `5m` 收盘 `c_{t-1} <= B_hi * 1.002`，且未追高过度：`c_t <= B_hi * 1.015`）；
     - `5m` 成交额放量确认：`v_t >= 1.3 * mean(v_{t-12 .. t-1})`。
  5. **上方无压力（源文件 §5 第 108–109 行）**：检查 `<= t` 过去 `30` 天已收盘 `1d` / `4h` K 线中高于 `entry_price * 1.005` 的历史高点：
     - 要么上方**无任何 30 日历史高点**（突破即创 30 日新高，上方无套牢盘）；
     - 要么距下一个 `1d` 结构高点压力位的空间 **`RoomToNext1DHighR >= 3.5R`**（上方一马平川）。
  6. **极小结构止损可定义（源文件 §5 第 108 行、§9 第 159–160 行）**：
     - 止损设在突破前最近 `12` 根 `5m` K 线（1h 收敛平台）的因果拐点低点 `stop_px = min(low_{t-6 .. t-1})`（且不高于 `B_hi * 0.996`）；
     - 止损距离须满足 **`0.35% <= (entry_price - stop_px) / entry_price <= 2.20%`**（超出 `2.20%` 则违背「极小止损才拿得住」，放弃不追；同标的冷却 `4h`）。
- **判决门槛**：`OOS ΔNetR >= +0.18R`（`Mean(S1_OOS) - Mean(Baseline_OOS)`）、聚类稳健单侧 `p < 0.05`、`G_oos >= 15`。若 `G_oos < 15` 按 2b 规则据实报 `FAIL (underpowered, G_oos=...)`；若 95% CI 上界 `< 0` 标 `KILLED`。

### 3.4 F：箱体过滤 — 箱体中段与箱体内反弹负向过滤（过滤型）

- **源文件溯源**：
  - **§3 点位 6**（第 76、81 行）：「箱体内反弹：最差，有赚就跑（EP22 Turbo 案、EP18：主升结束→箱体震荡内的反弹）」。

- **因果操作化公式（作用于 kairos 基线候选票流，时刻 `entry_ts`，仅用 `<= entry_ts` 已收盘 `4h`/`1d`/`5m` 数据）**：
  - 取 `<= entry_ts` 最近 `30` 根已收盘 `4h` K 线（`5` 天结构区间）：设区间最高价 `H_box = max(high)`、最低价 `L_box = min(low)`、区间高度 `W_box = (H_box - L_box) / L_box`，以及近 `12` 根 `4h` K 线（`48h`）净位移效率比（Kaufman Efficiency Ratio）`ER_4h = |close[-1] - open[-12]| / sum(high - low for last 12 bars)`。
  - 计算当前入场价在 `5` 日箱体中的相对位置 `pos_box = (entry_price - L_box) / max(H_box - L_box, 1e-9)`，以及到上方 `4h/1d` 最近阻力的 `RoomToResistanceR`（多单）或下方支撑的 `RoomToSupportR`（空单）。
  - 一张票据在 `entry_ts` 被因果判定为 **`FILTERED_BOX`（被滤组：箱体中段 / 箱体内反弹）** 当且仅当 `W_box >= 3.0%` 且满足以下任一子条件：
    1. **箱体中段震荡单（源文件 §5 第 99 行「箱体中段方向不可知」）**：`ER_4h <= 0.30`（`48h` 处于低效率拉锯震荡而非单边趋势）**且** `0.25 <= pos_box <= 0.75`（开仓位置处于箱体中间 50% 无依托地带）；
    2. **主升结束后的箱体内反弹多单（源文件 §3 点位 6 第 81 行 + §5 第 102 行「箱体内不接多」）**：`direction == "UP"`、`H_box` 出现在至少 `>= 3` 根 `4h` K 线（`>= 12h`）之前且曾从 `H_box` 回落 `>= 5.0%`（前波上涨已结束转入箱体），当前仍压在箱体内部（`entry_price <= H_box * 0.985`，`pos_box < 0.85`）且上方受箱体内部/上沿阻力压制（`RoomToResistanceR < 2.0R`）。
  - **其余票据归入 `RETAINED_NON_BOX`（保留组）**。
- **判决门槛（严格按过滤器标准验）**：OOS 下必须同时满足：
  1. 被滤组 `FILTERED_BOX` 均值 NetR 的 **95% 聚类稳健 CI 上界 `< 0.0000R`**；
  2. **`Mean(RETAINED_NON_BOX) - Mean(FILTERED_BOX) >= +0.15R`**（并报聚类稳健 `p` 值）；
  3. 被滤组独立波次簇数 **`G_filtered >= 15`**。
  - **表述红线**：即使 PASS，结论也只能表述为「负向过滤剔除负期望烂票」，严禁表述为「保留组构成正期望进场信号」。

     - 其余情况（如独立行情或首波同步启动当下即 `wake_ts` 且当根 `5m/1h` 领涨大饼 `>= +0.5%`）→ 当下与 BTC 同向突破给 `+2`（若 `r_btc_1h >= +0.8%` 且 `r_sym_1h >= r_btc_1h + 0.8%`），否则 `0`。
3. **`S_3` BTC 调整期相对抗跌状态（源文件 §6 第 114 行③，取值 `0, +1, +2`）**：
   - 取 `<= wake_ts` 过去 `7` 天（`42` 根已收盘 `4h` K 线）中所有 BTC 下跌调整棒（`ret_btc_4h <= -0.5%`，至少 `>= 2` 根）：
     - 计算标的 `i` 在这些 BTC 调整棒上的平均超额收益 `res_mean = mean(ret_sym_4h - ret_btc_4h)` 与横盘不跌比例 `flat_ratio = mean(ret_sym_4h >= -0.25%)`：
     - 若 `flat_ratio >= 0.50` 且 `res_mean >= +0.40%`（大饼跌时横盘不调/逆势微涨）→ **`S_3 = +2`**；
     - 若 `res_mean > 0.0%`（跌得比大饼少，微调抗跌）→ **`S_3 = +1`**；
     - 否则 `S_3 = 0`。
4. **`S_4` 日线空间状态（源文件 §6 第 114 行④，取值 `-1, +1, +2`）**：
   - 基于 `<= wake_ts` 过去 `30` 天已收盘 `1d` K 线，计算当前价距上方最近日线高点（`high_1d > cur_px * 1.01`）的空间比 `space_pct`：
     - 上方无 30 日日线高点（创 30 日新高）或 `space_pct >= 12.0%` → **`S_4 = +2`**；
     - `6.0% <= space_pct < 12.0%` → **`S_4 = +1`**；
     - `space_pct < 3.0%`（紧贴日线重压）→ **`S_4 = -1`**（`3%..6%` 记 `0`）。
- **分组与评估口径**：
  - 在每次唤醒 `w`（候选数 `K_w >= 4`）内，按 `(S_total, S_3, S_2, quote_vol_24h)` 降序排列：
  - **头部组（`TOP_LEADERS`）**：每次唤醒排名前 **2** 名（对应源文件 §6 第 116 行「认定的两只龙头」）；
  - **其余组（`REST_CANDIDATES`）**：同次唤醒排名第 `3 .. K_w` 名的其余候选票据。
  - 全额计入交易摩擦与次新/低流动性冲击滑点（与 `h2_experiment.py` 100% 同一 `FrictionParams`）。
- **判决门槛**：OOS 下 **`ΔNetR = Mean(TOP_LEADERS) - Mean(REST_CANDIDATES) >= +0.15R`** 且聚类稳健单侧 **`p < 0.05`**（同时报告对比 `Current Ranker` Top-2 的边际提升作为参考）。

### 3.6 温度计（源文件 §1「结构好的票起不来 = 热钱撤退」）：可操作化诚实评估

- **源文件原文（§1 第 38、42 行；§6 第 116 行）**：
  - 「冬天的温度计：结构好+位置对+久未有行情，天时地利人和都齐的票都起不来（如 EP18 的 W）→ 热钱撤退的实锤；大饼弹 8% 却没有一个山寨弹 30–40% 的龙头 → 没人玩小票。结论动作是休息，不是找机会。」
  - 「他的做法是先休息两天观察，确认有残留热度才出手。」
- **可操作化评估结论：标 `UNTESTABLE`（严守「不许降格近似、不许硬凑」红线）**。
- **无法在 Phase 2b 数据集上忠实测量的三项硬缺失**：
  1. **全市场横截面缺失（27 标的池 vs 全市场 ~500 永续合约）**：源文件第二判据「大饼弹 8% 却没有一个山寨弹 30–40% 的龙头」是**全市场最大值存在性命题（$\max_{i \in \mathcal{U}} R_i < 30\%$）**。Phase 2b 仅拉取了 27 个标的（其中 15 个为 BTC/ETH/LTC/ADA/DOT 等低弹性大市值主流币，12 个为特定次新币，早中期活跃标的仅十余个），缺失其余 ~500 个活跃山寨永续合约的 `4h`/`1d` 历史行情。在 27 标的池上看到「无币涨 30%」，无法区分「全市场真的热钱撤退」与「领涨龙头落在未采样的 500 个山寨币中（严重漏采假阴性）」。
  2. **连续多日 1m 观测窗缺失（15h 离散切片 vs 48h 冷却期验证）**：温度计触发（「好结构突破失败起不来」）后，源体系规定动作是「休息两天（`48h`）观察」。但 Phase 2b 的 1m 票流由 `40` 个长仅 `15h`、间隔 `~9.15 天` 的离散切片构成——切片内一旦发生突破失败，后续 `48h` 休息期中平均超过 `80%` 的时间落在无 1m 数据的切片间隙内，无法在不篡改时间尺度的前提下观测后续 `48h` 被抑制票据的真实分布与簇样本量（`G >= 15`）。
  3. **前置逻辑依赖尚未成立**：「天时地利人和都齐的好结构票起不来」以系统已拥有经过样本外验证的正期望「好结构识别器」为逻辑前提（否则识别器自身的假突破噪声会被恒定误判为市场热钱撤退），且「久未有行情的沉寂板块轮动」（§1 第 42 行、§2 第 55 行动物园/AI 板块）需要全市场板块分类元数据，当前 DuckDB 表结构（仅含 OHLCV、24h Vol、Funding、OI、上币时间）无此字段。
- **未来解锁温度计验证所需补齐的数据清单**：
  1. 全市场 PIT 永续合约（`~500` 个 USDT-SWAP）完整连续 `4h` / `1d` K 线表（用于忠实计算「BTC 反弹 ≥8% 窗口内全市场山寨最大涨幅分布」）；
  2. 连续无间隔（或每次切片 `>= 72h`）的 1m 历史回放窗口（用于完整覆盖触发后 `48h` 冷却期的被滤票流）；
  3. 至少一项在 3a 中通过 OOS 正期望验证的「好结构」基准设置作为温度计探针。
