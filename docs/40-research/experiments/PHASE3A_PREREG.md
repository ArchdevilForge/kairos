## 2. 数据集、样本切分与统计口径（100% 沿用 Phase 2b + 交割单尺度校准）

### 2.1 数据集锚点（沿用 `PHASE2B_PREREG.md`）
- **时间跨度**：`2025-11-09T00:00:00Z`（`1762646400`）至 `2026-11-09T23:59:00Z`（`1794268740`），连续 `366` 个日历日（12 个月），严禁挑子窗口。
- **采样结构**：`40` 个等距连续 `1m` K 线切片（前 39 个切片各 `15h = 900` 根 1m K 线，间距 `~9.15 天 >> 24h`，第 40 个切片为末尾 `24h`）+ 全窗口连续 `4h` / `1d` HTF K 线（`fact_perp_bars_htf`）+ 因果滚动 24h 成交额（`fact_perp_volume_24h`）+ `8h` 资金费率（`fact_perp_funding_8h`）+ `5m` OI（`fact_perp_oi_5m`）。
- **PIT 标的池（`PHASE2B_27_SWAP_INST_IDS`）**：15 个主流/核心永续合约 + 12 个 2025–2026 期间上线或中小流动性永续合约（共 27 标的）。任何时刻 `t` 严格校验 `list_ts <= t` 且 `(delist_ts IS NULL OR delist_ts > t)`。
- **步骤 0 验收硬门槛**：重演落库后 `fact_perp_bars_1m` 总行数须在 `758,013 ± 2%`（即 `[742,853, 773,173]`）内，超差即停机报告。

### 2.2 样本切分（沿用 Phase 2b 的 IS / Walk-Forward OOS 切法）
- **Wave 聚类**：所有事件/票据严格按 `tools/research/clustering.py:build_wave_clusters` 的 `< 24h`（`86,400s`）合并规则生成独立宏观波次簇 `wave_cluster_id`。由于相邻 1m 切片间隔 `~9.15 天 >> 24h`，全窗口最多形成 `40` 个独立波次簇。
- **IS / OOS 切分**（与 `tools/research/h3_experiment.py:621-628` 及 `h1_experiment.py:690-728` 完全一致）：
  - **In-Sample（IS / Full Window）**：全部波次簇 `all_cluster_ids`（诊断展示）。
  - **Walk-Forward Out-of-Sample（OOS，所有判决的主口径）**：将首个波次簇 `all_cluster_ids[0]` 作为初始预热校准簇，其后的全部独立波次簇 `oos_cluster_ids = all_cluster_ids[1:]` 作为样本外测试集；任何用到历史参考分布的量只允许读取 `ts < cluster_start_ts` 的历史观测，且所有入场/过滤/排序特征均强制通过 `validate_ex_ante_grouping`（`feature_ts <= entry_ts`，零前视）。
  - **附加稳健性透明度列**：除上述与 2b 完全一致的 Walk-Forward OOS 主口径外，报告同时附列严格按日历前 30% 簇（前 12 个切片）与后 70% 簇（后 28 个切片）不重叠切分的诊断结果；**最终 PASS/FAIL 判决唯一绑定上述 2b 标准 Walk-Forward OOS 口径，严禁在两种切分间挑结果**。

### 2.3 统计口径与基线票流（沿用 Phase 1/2b `PolicyNetR` + `CR1`）
- **收益标尺（`PolicyNetR`）**：统一使用 Phase 1 P0 平台期胜出策略 `wave_k_be=0.8`（`tools/research/policies.py:simulate_holding_policy`，`max_hold_minutes=1440`）：
  - 1m K 线内同时触及止损与目标/保本触发位时，严格按 **`stop-first`（最坏路径优先）** 结算；
  - 含手续费保本止损在确认分钟收盘后，于**下一分钟开盘**生效；
  - 15m/1h/4h 因果抬高波段低点（HL）移动止盈仅使用 `close_ts <= bar.open_ts` 的已收盘 K 线；
  - 全额扣除双边 Taker 5 bps、基础滑点（主流 1.5 bps / 山寨 5.0 bps）、平方根市场冲击滑点 `0.5 * (ATR_1m / P) * sqrt(V / ADV_5m)`（单笔名义本金 `$10,000`）以及持仓跨越的 `8h` 资金费率。
- **聚类稳健推断**：统一使用 `clustering.py` 的 `cluster_robust_mean` 与 `cluster_robust_diff`（`CR1` 聚类稳健三明治方差，按 `wave_cluster_id` 聚类，自由度 `df = G - 1`，双侧 95% Student-t 置信区间与单侧 `student_t_one_sided_p`）。
- **基线票流定义（`Baseline Ticket Stream`）**：
  - 沿用 `tools/research/h1_experiment.py:run_h1_experiment` 的既有因果候选票据生成器（PIT 有效合约、`24h` 成交额门槛 `$30,000,000`、5m 横截面唤醒 + `_detect_5m_pullback_trigger` 因果触发，即 Phase 2b `N = 1,550`、`G = 40` 的同一条 kairos 标准候选票流）。
  - 鉴于源文件 §11 与 `episodes/01-20231028.md` 第 8 行（「主升浪里零空单：从来不做逆势单」）及改造总纲映射表（「点位 3/5 摸顶空默认排除，默认 OUT，不进 3a」），S1/S2/S3 均为顺势多头设置：
    - **S1 / S2 的比较基线**：主口径对比同一 OOS 波次窗口内的**基线多头票流**（`direction == "UP"`），同时在报告中透明列出对比**全方向基线票流**（`UP + DOWN`）的数值作为核查参照；主判决绑定对基线多头票流的 `OOS ΔNetR`。
    - **S3 / F 的全票流**：直接在上述 kairos 既有候选票流上做因果划分（S3 在既有顺势多头 pullback 票流上划分「满足浪浪小分歧四约束保留组」vs「违背约束剔除组」；F 在基线票流上划分「箱体中段/箱体内反弹/非主跌箱体空被滤组」vs「其余保留组」）。
    - **L 的比较基线**：沿用 `tools/research/h2_experiment.py` 的同一多候选横截面唤醒池（`min_quote_vol_24h = $10,000,000`，每次做多唤醒至少 `>= 4` 个有效候选标的），在同一唤醒内取浪浪共振龙头分 **Top-2（头部组）** vs **其余候选（其余组）**。

#### 3.5.2 L 的因果状态打分公式（严格在每次做多唤醒 `wake_ts <= entry_ts` 计算）
在 `h2_experiment.py` 同一多候选唤醒协议下（`direction == "UP"` 多头唤醒，PIT 有效且 `24h` 成交额 `>= $10M`，候选数 `K_w >= 4`），对每个候选标的 `i` 用 `<= wake_ts` 已收盘 `1d`/`4h`/`5m` 数据打四项离散状态分 `S_total(i) = S_1 + S_2 + S_3 + S_4`（总分范围 `[-4, +8]`）：
1. **`S_1` 日线结构与近 48h 动态流畅状态（`EP21` 第 7–9 行、`DELIVERY_AUDIT.md` §4，取值 `-1, 0, +1, +2`）**：
   - 若上线不足 `7` 天（`age_days < 7.0`，未洗盘收敛，`EP05` 第 10 行）或过去 `14` 天已极端透支滞涨（`ret_14d > +85%` 且近 `3` 根 `4h` 涨幅 `<= 0` 或近 `48h` `ER_4h < 0.25`，老龙头高位不流畅，`EP21` 第 9 行 / `EP22` 第 8 行）→ `S_1 = -1`；
   - 否则：若已收盘日线满足 `close_1d > SMA_1d(7) >= SMA_1d(20)` 得 `+1`；若近 `48h`（`12` 根 `4h`）走势流畅度 `ER_4h >= 0.35`（少插针、高实体推进，区分 PEOPLE/WLD 与 TRB）且近 `14` 日曾有单日涨幅 `>= +5%` 股性表现（`EP21` 第 7 行①③）再得 `+1`（最高 `+2`）。
2. **`S_2` 主流启动先行/同日共振状态（`EP06` 第 14 行、`EP07` 第 10 行、`EP13` 第 9–11 行、`EP21` 第 6 行，取值 `-2, 0, +2`）**：
   - 识别 `<= wake_ts` 最近 `72h` 内 BTC（及 ETH）最近一次 `4h` 启动或平台破位事件 `t_major_launch`（单根 `4h` 涨幅 `>= +1.2%` 或收盘突破前 `12` 根 `4h` 高点）：
     - 若存在 `t_major_launch`，且标的 `i` 在 **`[t_major_launch - 4h, t_major_launch + 8h]`**（覆盖 `EP06`/`EP07`「大饼盘整末期山寨略早试错」与「同日首段共振」）内涨幅超过同期候选池中位数 `+1.0%` 以上 → **`S_2 = +2`（共振先发状态）**；
     - 若过去 `48h` 主流已累计涨 `>= +2.5%`（处于涨后中后段）且 `wake_ts - t_major_launch > 12h`，而标的 `i` 在 `[t_major_launch - 4h, t_major_launch + 12h]` 内涨幅 `<= +0.5%`（第一波完全缺席，当期才滞后补涨）→ **`S_2 = -2`（补涨币降级，`EP14` 第 12 行、`EP22` 第 7 行）**；
     - 若当期即为首波同步启动窗口（`t_major_launch` 不存在或 `wake_ts - t_major_launch <= 8h`）且近 `1h` 同步领涨主流 `>= +0.8%`（`r_major_1h >= +0.8%` 且 `r_sym_1h >= r_major_1h + 0.8%`）→ **`S_2 = +2`**，否则 `0`。
3. **`S_3` BTC 调整期相对抗跌状态（总纲 §6 第 114 行③、`EP03` 第 7 行，取值 `0, +1, +2`）**：
   - 取 `<= wake_ts` 过去 `7` 天（`42` 根已收盘 `4h` K 线）中所有 BTC 下跌调整棒（`ret_btc_4h <= -0.5%`，至少 `>= 2` 根）：
     - 若横盘不跌比例 `flat_ratio = mean(ret_sym_4h >= -0.25%) >= 0.50` 且平均超额 `res_mean = mean(ret_sym_4h - ret_btc_4h) >= +0.40%` → **`S_3 = +2`**；
     - 若 `res_mean > 0.0%` → **`S_3 = +1`**；否则 `0`。
4. **`S_4` 日线空间状态（总纲 §6 第 114 行④、`EP13` 第 11 行，取值 `-1, 0, +1, +2`）**：
   - 基于 `<= wake_ts` 过去 `30` 天已收盘 `1d` K 线，计算距上方最近日线高点（`high_1d > cur_px * 1.01`）空间比 `space_pct`：无 30 日高点或 `space_pct >= 12.0%` 得 `+2`；`6.0% <= space_pct < 12.0%` 得 `+1`；`space_pct < 3.0%` 得 `-1`；其余 `0`。
- **分组与判决门槛**：每次唤醒（`K_w >= 4`）按 `(S_total, S_3, S_2, quote_vol_24h)` 降序取 **Top-2（`TOP_LEADERS`）** vs **其余（`REST_CANDIDATES`）**；PASS 要求 OOS **`Mean(TOP_LEADERS) - Mean(REST_CANDIDATES) >= +0.15R`** 且聚类稳健单侧 **`p < 0.05`**。

### 3.6 温度计（源文件 §1 + `EP18` 第 12 行 + `EXTRA` 第 6 行）：可操作化诚实评估

- **源文件与逐集模板原文**：
  - `episodes/18-20240504.md` 第 12 行：「W 天时地利人和（结构好+大饼反弹拐点+久未有山寨行情）都起不来 → 判定热钱撤退、没人玩小票；大饼弹 8% 却没有一个山寨弹 30–40% 的龙头 → 结论是休息。」
  - `episodes/extra-20240309.md` 第 6 行（两种冬天）：「位置一的冬天是大跌砸完、全面熄火……位置二的冬天在新高附近……他的操作：砸完先彻底休息两天（`48h`）观察，确认是『有残留热度的冬天』才出手 WLD。」
  - `episodes/22-20240601.md` 第 8 行：「他俩（PEOPLE/BB）如果都起不来，山寨也别想有行情——龙头是山寨行情的开关。」
- **可操作化评估结论：标 `UNTESTABLE`（严守「不许降格近似、不许硬凑」红线）**。
- **无法在 Phase 2b 数据集上忠实测量的三项硬缺失**：
  1. **全市场横截面缺失（27 标的池 vs 全市场 `528` 个 PIT 永续合约）**：`EP18` 第 12 行「大饼弹 8% 却没有一个山寨弹 30–40% 的龙头」是全市场最大值存在性断言（$\max_{i \in \mathcal{U}} R_i < 30\%$），当前 DuckDB 仅拉取 27 个标的（缺失其余 ~501 个活跃合约的 `4h`/`1d` 行情），无法区分「全市场无 30% 龙头」与「龙头落在未采样合约中」。
  2. **连续 48h 冷却观测窗缺失（15h 离散切片 vs `EXTRA` 第 6 行 48h 休息观察期）**：`EXTRA` 第 6 行明确规定触发后「先彻底休息两天（`48h`）观察」，而 Phase 2b 的 1m 票流由 `40` 个长仅 `15h`、间隔 `~9.15 天` 的离散切片构成，触发后 `48h` 逾 `80%` 落在无 1m 数据的空白期，无法忠实计量被抑制票流与簇数（`G >= 15`）。
  3. **前置正期望好结构探针与沉寂板块元数据缺失**：`EP18`「久未有行情的板块 / 天时地利人和好结构票起不来」依赖全市场叙事板块分类（动物园/AI/铭文）及已通过样本外验证的正期望结构探针，当前 schema 无板块分类字段。
